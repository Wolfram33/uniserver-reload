🚀 Quick start

The all-in-one package ships the complete server in one self-extracting archive — no installation, no dependencies, no configuration.

  1. Download UniServer-Reload.exe from the releases page and run it.
  2. Choose an empty target folder (no spaces in the path, not under C:\Program Files), e.g. C:\UniServer-Reload. The server extracts directly into it.
  3. Start UniController.exe from that folder, then click Start Apache and Start MariaDB.
  4. Put your site into the www subfolder — or point a Vhost straight at your project folder (see Virtual hosts).
Everything below is preconfigured. This page describes the fork; the original ZeroXV reference manual is linked at the bottom.

🐘 PHP versions 8.3 · 8.4 · 8.5

Switch the active PHP version from the controller — Apache loads it as a module.

  1. Stop Apache.
  2. PHP > Select PHP version → pick 8.3, 8.4 or 8.5.
  3. Start Apache again.

Every version ships with these extensions enabled by default (in all ini variants, including php-cli.ini for scripts and cron): pdo_mysql, pdo_sqlite, sqlite3, mysqli, gd, mbstring, exif, openssl, fileinfo, curl. Enable more via PHP > Edit Basic and Modules.

🔒 HTTPS & certificates

https://localhost works out of the box: on first start the controller generates a self-signed certificate (covering localhost, 127.0.0.1, ::1) and enables SSL. When SSL is on, the controller opens the start page as https://.

Remove the browser warning

  1. UniController asks on its first start whether to trust the certificate → confirm with Yes and accept the Windows prompt. (Any time later: Apache > Apache SSL > Trust certificate in Windows.)
  2. Restart the browser completely (Chrome: chrome://restart).
One certificate covers localhost and all your Vhost domains. Both HTTP and HTTPS serve the same www folder — and with Vhosts, unknown host names (e.g. access by IP) fall back to www on both ports.
Firefox ignores the Windows certificate store by default. When Firefox is installed, the controller offers (once, after trusting) to enable Mozilla's official ImportEnterpriseRoots policy for the current user so Firefox uses the Windows store too — undo by deleting the value under HKCU\Software\Policies\Mozilla\Firefox\Certificates. Alternatively import the certificate manually in Firefox's certificate settings.

🌐 Virtual hosts

Give each project its own hostname — pointing directly at your project folder, no copying into www. Create as many as you like: the controller writes the Windows hosts file entries itself (deduplicated and verified — the upstream limitation that only one vhost ever resolved is fixed in this fork).

  1. Apache > Apache Vhosts > Create Apache Vhost.
  2. Document root: a plain name (portable, created under vhosts\) or click Browse… and choose any folder, e.g. D:\projects\app.
  3. Server name, e.g. app.test — the controller adds it to the Windows hosts file automatically.
  4. Create Vhost → the certificate is rebuilt automatically to cover the new domain; answer the trust question with Yes → restart the browser → restart Apache.

http://app.test and https://app.test both serve your project. mod_rewrite, AllowOverride All and FollowSymLinks are set, so .htaccess rewrites work immediately.

Deleting a Vhost only offers to remove folders created under vhosts\. An external project folder you pointed to is never deleted. The built-in default host (the localhost/www fallback) is protected and never listed for deletion.

🗄️ Databases

MariaDB is the database engine since 1.3.6 (the long-term-support release with the longest remaining support, see the splash page for the exact version). It lives in core\mysql and answers on port 3306 like MySQL did, so apps, phpMyAdmin and the controller menus work unchanged. MySQL 8.4 LTS remains available as a module (UniServer-Reload_mysql_module.zip).

AdminphpMyAdmin via the phpMyAdmin button. Default login root / root.
HostUse 127.0.0.1 as the DB host in your apps (not localhost) for a reliable IPv4 connection.
Hot backupscore\mysql\bin\mariadb-backup.exe --backup --target-dir=... copies a running server without locking it (MariaDB only).
Coming from 1.3.5 or olderThose bundles ran MySQL 8.2. Export the databases there first (MySQL > Database backup), then import the dumps into MariaDB (MariaDB > Database restore). Copying core\mysql\data across does not work.

I want MySQL, not MariaDB

No problem: MySQL 8.4 LTS ships as the module UniServer-Reload_mysql_module.zip on the releases page, built by the same CI from Oracle's download. It replaces the engine in place; apps, phpMyAdmin, mysqli/PDO and every controller function work the same. In the controller, MariaDB > Switch to MySQL instead… shows these steps as well.

  1. Export the databases you need: MariaDB > Database backup (or core\mysql\bin\mysqldump.exe). The two engines cannot read each other's data folder.
  2. Stop MariaDB and delete the folder core\mysql completely - a mix of both engines' files corrupts the data folder.
  3. Unzip the module into the server folder (the folder with UniController.exe). It brings a fresh core\mysql: root password root, phpMyAdmin control user and tables included.
  4. Restart the controller - the menus now say MySQL - and import the dumps via MySQL > Database restore. Recreate restricted users (MySQL > Create restricted MySQL user); single-database dumps do not carry them.
MySQL 8.4 uses the caching_sha2_password login by default. The bundled PHP handles it; very old external tools may not. Switching back to MariaDB works the same way with UniServer-Reload_mariadb_module.zip.

✉️ E-mail

PHP mail() is wired to the bundled msmtp client. Enter a real SMTP account in core\msmtp\msmtprc.ini (ready-made blocks for port 587/465 and Gmail are included), then set account default : <name>. Test with core\msmtp\Send_test_email.bat.

Outgoing mail automatically gets the Date, Message-ID, MIME-Version and Content-Type headers spam filters expect, and TLS certificate checking is on (CA bundle included). For good deliverability: send through an authenticated provider (DKIM), keep From: aligned with that account, and set up SPF/DMARC for your domain.

🧯 Troubleshooting

PHP source shown instead of running

Restart Apache after switching PHP version, and open the page through the server (http://localhost/…), not as a file://. Check core\apache2\logs\error.log.

“could not find driver” (PDO)

Enable the DB extension for the active version: PHP > Edit Basic and Modules → tick pdo_sqlite+sqlite3 or pdo_mysql → restart Apache.

HTTPS still warns after trusting

Run Regenerate certificate for all Vhosts, trust again, and fully restart the browser. Verify the names:

core\apache2\bin\openssl.exe x509 -in core\apache2\server_certs\server.crt -noout -ext subjectAltName

If a domain sent HSTS before, clear it at chrome://net-internals/#hsts.

Path rules

No spaces in the install path; don’t use C:\Program Files. Absolute Vhost paths are not portable across machines.
